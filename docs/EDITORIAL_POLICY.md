# Documentation editorial policy

**Authority:** Human-approved. Owners are authorized to curate documentation within their paths under this policy.

Keep a concise, navigable set of focused documents with one authoritative home for each fact. `PRODUCT_BRIEF.md` records product intent. `ARCHITECTURE.md` and `api/` define technical boundaries and contracts. `ROADMAP.md` tracks approved scope and maturity. `USE_CASES.md` is the home for major workflows and design. Module documentation holds the detail needed to use and maintain each module. Keep root guidance brief and link to the relevant detail.

For current acceptance, record the verified outcome, build and target, important limits, and open checks together. Link evidence where useful, and state its scope plainly. Update affected documentation alongside feature changes.

Documentation owners may remove redundant or superseded guidance and repair references within their owned paths under this policy. Git history is sufficient by default for removed wording. Do not duplicate old prose or create new records solely to preserve it. Avoid duplicate active documents and per-file leadership sign-off. The owner map in the root README and the team coordination agreement define path ownership. Project Manager coordinates cross-owner moves and disputed scope.
