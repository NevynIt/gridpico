# Documentation editorial policy

**Authority:** Human-approved. Owners are authorized to curate documentation within their paths under this policy.

Keep a concise, navigable set of focused documents with one authoritative home for each fact. `PRODUCT_BRIEF.md` records product intent. `ARCHITECTURE.md` and `api/` define technical boundaries and contracts. `ROADMAP.md` tracks approved scope and maturity. UI Designer owns `USE_CASES.md` as the home for major workflows and visual design. Module documentation holds the detail needed to use and maintain each module. Keep root guidance brief and link to the relevant detail.

For current acceptance, record the verified outcome, build and target, important limits, and open checks together. Link durable evidence where useful and state its scope plainly. A retained artifact or pinned revision must identify the evidence. A scratch log alone is transient. Update affected documentation alongside feature changes.

Owners apply this policy during normal documentation review. Keep active contracts, operating and recovery instructions, and open acceptance checks. Remove superseded historical and evidence prose from active guidance and repair inbound links when retiring content. Git history is the archive. Add a short pointer to a previous pinned commit only when it helps a current reader. Do not copy archives or logs elsewhere, keep stale sections solely to preserve evidence, or treat this policy as authority for broad deletion. Owners curate within their paths without per-file leadership sign-off. Cross-owner moves require approval from affected owners, and Project Manager coordinates those moves and disputed scope. The root README and team coordination agreement define path ownership.
