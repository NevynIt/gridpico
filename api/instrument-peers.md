# Optional MIDI instrument peers

**Owner** Architect. **Status** Stock FluidSynth, the standalone wrapper and browser FM verified in their respective bench profiles. [Browser MIDI](browser-midi.md) · [Local production router](local-router.md).

A sound-generating peer is an optional, independently launched MIDI destination. The router delivers MIDI through existing selectable ports and owns route and note-release accounting. A peer owns its synthesis engine, voices, settings and local audio output. The Gridpico kernel and Pico firmware handle MIDI. Independently running components continue to exchange MIDI or the independent serial CLI byte stream. An audio file retrieved for testing is a bench artifact.

## Stock FluidSynth proof on `rpi0`

Use stock FluidSynth with a documented SoundFont and a selected ALSA sequencer MIDI input. Route a short held Note On/Off pair through the production Pi router to that port. Capture a short WAV from the live file driver or another verified capture sink, record the MIDI receipt and verify the tone, release tail and return to the background level. Retrieve the WAV and evidence manifest by SFTP and verify the checksum. Record package version, SoundFont provenance, rights and checksum, selected route and audio settings. Keep an offline MIDI-file render, actual routed audio and physical listening as separate results. Label an RTP-routed WAV only after the actual cross-host leg is exercised. Independent checks verified the locally routed WAV's attack, release tail and final silence and matched its checksum after SFTP retrieval. Physical playback and an RTP-routed WAV remain open. ## Standalone FluidSynth wrapper

The wrapper launches and stops the installed engine and selects the local MIDI input, SoundFont and audio sink or file. It owns its configuration and lifecycle and uses the system FluidSynth package. Review the exact licensing and notices before distributing any library, SoundFont or rendered sample with the product. The production router sees the wrapper's MIDI port and applies its normal release, route and CLI contracts. Independent Pi testing of `efc4707` verified routed Note On and Off, decay and final silence, and WAV finalization on Ctrl+C. [Run the wrapper](../instruments/fluidsynth/README.md) · [FluidSynth licensing](https://www.fluidsynth.org/wiki/LicensingFAQ/)

The opt-in Pi deployment uses a fresh file-driver engine for each take and exposes the completed WAV through the Pi host. [Pi recorder contract](pi-recorder.md)

## Standalone browser FM instrument

Open one selected receive binding from the shared browser MIDI layer. A user enables Web Audio explicitly. Start with one built-in FM voice and ordinary Note On and Note Off. Interpret velocity-zero Note On as Note Off. Keep a bounded local voice allocation and release the matching voice on Note Off. Immediately silence or cancel remaining voices on disconnect, input change or audio disable. The FM page owns its DSP and local settings independently of Monitor.

The tool shipped in `130c9ed` at `/fm/` with an original built-in voice. The loopback home links to it and the staged offline home links to self-contained `FM.HTM`. Independent Chromium checks verified routed Note On and Off and voice cleanup through loopback WebSocket, plus playback and device-loss cleanup on a selected real ALSA Web MIDI port. Staged direct-file opening passed. Mounted Pico permissions and browser playback through an OS-exposed RTP port remain separate. Audit code, dependency, patch and sample rights before bundling future material. ## Optional hosted Web Synth

A separately hosted fork of Ameobea's Web Synth may add one optional receive-only WSS MIDI input to the existing MIDI event path. Retain upstream UI and Web MIDI. The WSS input decodes Note On and Note Off, treats zero-velocity Note On as Note Off, and releases its voices when the connection closes or is replaced. Keep synthesis and assets in the separate project. Gridpico links and credits the approved deployment. The bundled FM tool remains the offline option.

The private same-LAN bench verified actual routed audio from the pinned engine. Router-side opt-in can ship independently with Gridpico's own transport code and documentation. Distribution of the synth requires complete corresponding source, dependency and asset notices, and a compatible license for the emitted bundle. External origin, operator identity enrollment and any applicable public-to-LAN browser permission still require separate approval and verification. An upstream PR also requires separate human approval. ### Private same-LAN evidence and release status

Independent headed Chrome testing used the frozen `fm-candidate` with the actual AudioWorklet and Wasm. Production WSS delivered exact managed MIDI bytes for a held note and its release. Browser PCM RMS was `0.22962054154104317` for the routed note and `0` after release. After transport loss it was `0`, and a fresh attack after reconnection measured `0.12808592707300062`. Cleanup preserved an independently held local note. The test also verified real ALSA Web MIDI input before WSS selection and its restoration after explicit close and transport loss. The exercised page made no external asset requests. These results describe the isolated private LAN and browser PCM.

The private fork leaves upstream Web MIDI unchanged. In the owner’s direct ALSA Web MIDI probe, an explicit Note Off produced an ungate and browser PCM returned to zero. A zero-velocity Note On did not ungate in this upstream revision. The new WSS input normalizes zero-velocity Note On to Note Off. The production router independently emitted a canonical Note Off when its managed ingress received the zero-velocity form.
