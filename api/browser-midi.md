### Automatic page admission

The ordinary server launched by `scripts/web-ui.sh` owns admission. A tool joins the selected server URL automatically by declaring its supported directions and roles. Operators supply no port numbers or per-page profile. Any supported page may join first. An instance gets its own endpoints, queues and binding authority within the server's bounded runtime. The descriptor `instance` identifies the runtime and is separate from the page allocation.

Like USB device registration, admission treats display names and capability labels as metadata. The page provides an advertised display name. Accept it verbatim if it passes the same validation, including duplicates from the same tool. The server issues the instance identity, secondary disambiguator and logical endpoint IDs. The tool template defines eligible capabilities and resource bounds without substituting a singleton name or slot. Roles are unique within an instance's bundle. Different instances can claim the same role under their own tickets, sockets and binding generations.

The request carries up to 1 KiB of JSON with version `1`, the current `runtime` token from the descriptor, a supported `tool`, its advertised `name`, and a `roles` array of `{role, direction, capability}`. Declarations supply no port IDs, generations or grants. The join stays inside the existing local authority, with no new serial, CDC, alternate-Origin, LAN or WSS grant.
