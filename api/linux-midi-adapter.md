# Linux ALSA MIDI adapter scope

**Owner** Architect. **Status** Integration ABI for the ongoing Linux↔Linux RTP-MIDI gate. [C11 declarations](linux_midi.h) · [Local router](local-router.md).

Linux HAL supplies one ALSA sequencer adapter. Assembly owns its lifetime, selected endpoint bindings and serialized calls into the production router. The production CLI retains inventory, route selection and committed status. `rtpmidid` provides the standard RTP-MIDI sessions as an installed OS peer. The adapter deals only with ALSA ports and MIDI bytes. [ALSA sequencer](https://www.alsa-project.org/alsa-doc/alsa-lib/seq.html) · [rtpmidid](https://github.com/davidmoreno/rtpmidid)

Windows RTP-MIDI is an approved product path through native OS-presented MIDI ports, with acceptance deferred to its nominated target. The [WebSocket MIDI profile](websocket-midi.md) has its own wire and acceptance gate. [Windows RTP-MIDI endpoints](https://microsoft.github.io/MIDI/sdk-reference/Transports/Rtp/)

- `open` and `close` own the native adapter handle. `list` copies a bounded set of current port addresses, readable names and permissions into caller storage. Count-only with capacity zero is valid. For an undersized buffer, return `GRIDPICO_CAPACITY` and the required count without a partial list. A listed address is a current OS selection. Assembly resolves a fresh, unambiguous address for each attachment and retains router logical IDs independently.
- `bind` checks the selected port's direction and successful subscription. A port that can be read feeds a graph input. A port that can be written accepts graph output. A bidirectional port can bind both independently to distinct logical connections. Assembly supplies the connection's generation and uses the existing graph lifecycle updates. `unbind` removes only that exact connection. A stale address or generation leaves live bindings untouched.
- `send` and `next` use complete three-byte MIDI 1.0 messages from the local supported set. Keep the original status and data bytes through ALSA conversion, including `96 00 00`. Send directly to the selected destination. `send` returns `GRIDPICO_OK` when ALSA accepts the event locally, `GRIDPICO_CAPACITY` for bounded queue exhaustion and `GRIDPICO_UNAVAILABLE` for an unavailable binding or driver. `next` is nonblocking and returns `GRIDPICO_OK` with `has_event=false` when there is no event. It exposes received bytes only for the matched live input connection. Assembly services it in bounded batches. [ALSA MIDI byte conversion](https://www.alsa-project.org/alsa-doc/alsa-lib/group___m_i_d_i___event.html)
- Report selected port removal, matching subscription loss or I/O failure per affected generation. Assembly retires that binding and propagates scoped cleanup through Graph. Evidence of ALSA subscription establishes a local path. The RTP gate separately verifies which selected OS event reliably signals peer loss. An advertised or persistent port and a quiet stream are insufficient evidence of peer liveness or loss. Prefer session-specific endpoints whose subscription and removal can be correlated with the actual peer. A fresh verified bind uses a new generation. Local sends and actual remote receives have separate trace evidence.

Only the opt-in native Linux target compiles and links ALSA. Use C11, CMake `find_package(ALSA REQUIRED)` and `ALSA::ALSA` on that target. The user-space prerequisite on Debian-derived systems is `libasound2-dev` at build time and its matching `libasound` runtime. The portable router and loopback builds keep their current dependencies. Bench reports identify the installed ALSA and `rtpmidid` versions, exposed devices, access settings and actual fault behavior. [CMake FindALSA](https://cmake.org/cmake/help/latest/module/FindALSA.html) · [Debian ALSA development package](https://packages.debian.org/stable/libasound2-dev)
