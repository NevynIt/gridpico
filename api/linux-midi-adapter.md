# Linux ALSA MIDI adapter scope

**Owner** Architect. **Status** Native ALSA adapter implemented and verified locally. Linux↔Linux RTP-MIDI exact receipt and scoped cleanup verified on selected sessions. [C11 declarations](linux_midi.h) · [Local router](local-router.md).

Linux HAL supplies one ALSA sequencer adapter. Assembly owns its lifetime, selected endpoint bindings and serialized calls into the production router. The production CLI retains inventory, route selection and committed status. `rtpmidid` provides the standard RTP-MIDI sessions as an installed OS peer. The adapter deals only with ALSA ports and MIDI bytes. [ALSA sequencer](https://www.alsa-project.org/alsa-doc/alsa-lib/seq.html) · [rtpmidid](https://github.com/davidmoreno/rtpmidid)

The `3e82eda` bench used production x86-64 and arm64 Pi routers with real ALSA and stock `rtpmidid` 26.01. It recorded exact Pi-side receipts, one scoped held-note release before Pending on orderly detach, fresh-generation rebind and one scoped release at peer expiry after abrupt daemon loss. Other attempts timed out or lacked remote receipts. The `699bac5` repeat attempts yielded no new RTP receipt. Repeatability, controlled transmitted Note Off loss, latency and Web MIDI through an OS-presented RTP port remain open. [Linux RTP bench](../ROADMAP.md#4-verify-rtp-midi-and-productize-cross-host-websocket-midi) · [Repeat attempt](../ROADMAP.md#approved-tonight-delivery)

Windows RTP-MIDI is an approved product path through native OS-presented MIDI ports, with acceptance deferred to its nominated target. The [WebSocket MIDI profile](websocket-midi.md) has its own wire and acceptance gate. [Windows RTP-MIDI endpoints](https://microsoft.github.io/MIDI/sdk-reference/Transports/Rtp/)

- `open` and `close` own the native adapter handle. `list` copies a bounded set of current port addresses, readable names and permissions into caller storage. Count-only with capacity zero is valid. For an undersized buffer, return `GRIDPICO_CAPACITY` and the required count without a partial list. A listed address is a current OS selection. Assembly resolves a fresh, unambiguous address for each attachment and retains router logical IDs independently.
- `bind` checks the selected port's direction and successful subscription. A port that can be read feeds a graph input. A port that can be written accepts graph output. A bidirectional port can bind both independently to distinct logical connections. Assembly supplies the connection's generation and uses the existing graph lifecycle updates. `unbind` removes only that exact connection. A stale address or generation leaves live bindings untouched.
- `send` and `next` use complete three-byte MIDI 1.0 messages from the local supported set. Keep the original status and data bytes through ALSA conversion, including `96 00 00`. Send directly to the selected destination. `send` returns `GRIDPICO_OK` when ALSA accepts the event locally, `GRIDPICO_CAPACITY` for bounded queue exhaustion and `GRIDPICO_UNAVAILABLE` for an unavailable binding or driver. `next` is nonblocking and returns `GRIDPICO_OK` with `has_event=false` when there is no event. It exposes received bytes only for the matched live input connection. Assembly services it in bounded batches. [ALSA MIDI byte conversion](https://www.alsa-project.org/alsa-doc/alsa-lib/group___m_i_d_i___event.html)
- Report selected port removal, matching subscription loss or I/O failure per affected generation. Assembly retires that binding and propagates scoped cleanup through Graph. Evidence of ALSA subscription establishes a local path. The RTP gate separately verifies which selected OS event reliably signals peer loss. An advertised or persistent port and a quiet stream are insufficient evidence of peer liveness or loss. Prefer session-specific endpoints whose subscription and removal can be correlated with the actual peer. A fresh verified bind uses a new generation. Local sends and actual remote receives have separate trace evidence.

Only the opt-in native Linux target compiles and links ALSA. Use C11, CMake `find_package(ALSA REQUIRED)` and `ALSA::ALSA` on that target. The user-space prerequisite on Debian-derived systems is `libasound2-dev` at build time and its matching `libasound` runtime. The portable router and loopback builds keep their current dependencies. Bench reports identify the installed ALSA and `rtpmidid` versions, exposed devices, access settings and actual fault behavior. [CMake FindALSA](https://cmake.org/cmake/help/latest/module/FindALSA.html) · [Debian ALSA development package](https://packages.debian.org/stable/libasound2-dev)

## Stage 3 USB identity seam

Stage 3 enables opt-in **verified USB input** attachment. An output selector can identify a candidate read-only. It reserves its logical output and leaves enabled routes Pending, even if identity resolves. It creates no subscription and sends no MIDI. Use an explicit operator-selected `LOGICAL CLIENT:PORT` row for numeric output attachment. USB selector resolution never falls back to that path.

The existing ALSA list supplies transient `client:port`, a display name and directional subscription capability. A kernel sequencer client can supply a hardware card number if the running kernel supports it. That is an observation for locating the card, and the USB driver parents the card to its first probe interface. The card number alone cannot identify a USB device or disambiguate MIDI interfaces. Userspace, virtual and RTP clients remain on their existing explicit address bindings. [ALSA client metadata](https://alsa-project.org/alsa-doc/alsa-lib/group___seq_client.html) · [Linux USB audio driver](https://github.com/torvalds/linux/blob/v6.18/sound/usb/card.c#L691-L719)

Assembly retains `LOGICAL CLIENT:PORT` in the local bindings file and accepts `LOGICAL usb VID:PID SERIAL_HEX INTERFACE` for the new opt-in path. Use four hex digits for each vendor and product ID, 2–128 even hex serial digits, and two hex digits for the USB interface number. Accept either hex case. Compare the decoded serial exactly as bytes. Direction comes from the registered logical port. The selector kind and USB identity for a logical port stay fixed for that runtime. A replacement identity requires a new runtime to keep prior release debt scoped to its original receiver. Explicit address bindings retain their existing operator-managed behavior.

Linux HAL owns correlation and subscription. Require an available card on a kernel ALSA client, a canonical USB MIDIStreaming interface for that card, and strong evidence that the interface is the device's sole MIDIStreaming interface. Require one USB device with the requested VID/PID and nonempty exact serial among present USB devices, the specified interface number, and exactly one corresponding MIDI-generic hardware sequencer port with the requested subscription direction. Unreadable or unstable observations, a missing or duplicate identity, or more than one eligible port remain unavailable. Name, current port index and topology alone do not establish continuity. This deliberately narrow selector excludes unsupported composite and multiport cases. [USB sysfs attributes](https://kernel.org/doc/html/v6.18/admin-guide/abi-testing-files.html)

The [C11 declarations](linux_midi.h) provide `resolve_usb` for current read-only observation, `bind_usb` for checked input subscription, and `check_usb_binding` for the existing exact verified input generation. A valid output bind returns `GRIDPICO_UNAVAILABLE` without changing subscription state, generation or the returned-address value. On input bind, verify again after subscription and undo it if identity, uniqueness, endpoint or subscription changed. Publish the address only on success. A stale, missing, ambiguous or unsupported observation returns `GRIDPICO_UNAVAILABLE`. Invalid arguments or invalid selector length return `GRIDPICO_INVALID`. Temporary resource exhaustion uses `GRIDPICO_CAPACITY`. These are private, serialized adapter calls.

An unresolved input selector reserves its logical port and leaves its enabled routes Pending. Initial attachment and explicit `SIGHUP` use the verified input path. Process observed retirement events first. Keep a healthy exact-generation subscription on rescan. Otherwise retire the old generation via the existing lifecycle, clean up only its held contributions at reachable outputs, and attempt a fresh verified input bind. The fresh input waits for a fresh press. Explicit numeric bindings and their existing routing and cleanup semantics are unchanged.

### Evidence and follow-on gate

Synthetic ALSA/sysfs checks exercise positive identity matching, ambiguous and unsupported cases, the output bind guard, and input rollback without consuming the attempted generation. The development host's real ALSA test covered an absent USB match staying Pending across rescan, reservation against virtual-port fallback, and continued exact MIDI on the unaffected explicit route. A separate real ALSA test verified explicit numeric input and output bindings. x86-64 and arm64 builds cover compilation. These results leave positive physical USB correlation and reattachment open. [HAL harness](../platform/linux/test_usb_identity.sh)

Verify a real input's card-to-USB correlation, held-note unplug, scoped release at a reachable explicit output, and verified same-device return on a fresh generation with no replay. Test address reorder or reuse and rejection of missing, duplicate or different identity. Record actual MIDI receipts and the unaffected routes separately. For a selected USB output, verify Pending across rescan and no traffic or fallback even if identity resolves.

Output activation requires a separate generation-bound transport and delivery-outcome review. The existing ALSA direct path checks a subscription and then sends to the numeric address. Subscriber routing also resolves numeric endpoints. In a controlled real ALSA sequencer test on development-host virtual ports, an exclusive subscription delivered a Note On. After the port was recreated at the same address, the old subscription was absent. Sending Note Off to the empty subscriber group returned 28 consumed bytes with zero receipt. A direct Note Off to the recreated numeric address also returned 28 bytes and reached the replacement. The write result leaves receipt of an attack or an owed release uncertain. [Linux sequencer dispatch](https://github.com/torvalds/linux/blob/v6.18/sound/core/seq/seq_clientmgr.c#L625-L737) · [Write result](https://github.com/torvalds/linux/blob/v6.18/sound/core/seq/seq_clientmgr.c#L985-L1007)

Before enabling verified USB output, demonstrate how the adapter distinguishes acceptance for the intended generation and preserves note obligations across uncertain results. Then exercise same-address reuse during held-note cleanup on the actual target. Record attempted old-generation release, local ALSA result and actual bytes at the replacement separately. Old-generation traffic at a replacement fails that gate.
